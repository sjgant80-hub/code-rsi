A cell that improves itself, with no model.

Rung 1's settling cell met 80 new writers whose digits were scanned differently. Here, plain code rewrites the cell's stored patterns one small change at a time. Each change is kept only if it wins on a fresh exam the cell has never seen, and the loop also retunes its own search from what it measures. No language model, no gradient, no network. Then it is judged once on writers it never trained on.

What this is

This is Rung 2 of a ladder toward computing by geometry instead of by large models. Rung 1 built a cell that reads handwriting by settling into one of a few stored patterns. Rung 2 asks whether that cell can get better by itself: can plain code, with no model inside, change the stored patterns so the cell reads new handwriting better, and prove the gain on people it never trained on?

That matters for the later rungs. A microcontroller cannot hold a model. If a defence on a chip is going to improve itself, the improvement has to come from code like this.

How it works

Step by step

  1. Start. The loop begins from Rung 1's frozen cell, byte for byte. On this new handwriting it is badly matched, because the two datasets frame digits differently.
  2. Propose. It picks one of six small edits by weight: nudge one pixel of one pattern; replace a pattern with a digit it just got wrong; move a pattern toward a recent mistake; push the wrongly winning pattern away from one; widen or narrow the reach; sharpen or soften the energy.
  3. Exam. It draws a fresh batch of 100 tune-half digits, each with a fresh 10% of its pixels replaced. No exam item is ever used twice. Both the current shape and the proposal settle every item.
  4. Gate. The change is kept only if it gets at least two more items right than it newly gets wrong. Otherwise it is thrown away.
  5. The recursive turn. The loop rewrites its own search. An edit type that keeps paying off gets picked more, and one that keeps failing gets picked less. A twin run with frozen weights is the control.
  6. Judge once. After 1,500 cycles each, both final shapes were frozen by hash, and only then was the blind half read.

    White paper: self-improvement without a model, judged on strangers

    The question. Most "self-improving AI" today means a large model rewriting things. A chip cannot hold one. Rung 2 asks whether plain code can improve a small settling cell by proposing edits and keeping only those that win on fresh exams, and whether the loop gains anything by tuning its own search.

    The method. UCI's Semeion handwritten digits: 1,593 digits from about 80 people, split 50/50 at a block boundary into a tune half and a blind half, as the dataset's notes recommend. The loop saw only the tune half, 100 fresh noisy exam items per cycle, for 1,500 cycles. A twin ran the same loop with its weights frozen. Both final shapes were frozen by hash before the blind half was read once.

      The limits, plainly:

      • Rung 1's cell starts badly on this data, because Semeion digits fill their box while the optical digits have margins. Beating it was the easy part; the harder claims are settling against one step, and the recursive turn against its twin.
      • Writer IDs are not in the dataset. The split falls on a block boundary that looks like a group of writers, so writer-disjoint halves are likely, not proven.
      • Exam items reuse tune digits under fresh noise. No item repeats, but the digits do, so a gain on the tune half alone proves nothing. Only the blind half counts.
      • One task, one dataset, one budget. Rung 2 is not a hybrid with step-code (Rung 3), not shared over a mesh (Rung 4), not a defence (Rung 5), and not on a chip (Rung 7).
